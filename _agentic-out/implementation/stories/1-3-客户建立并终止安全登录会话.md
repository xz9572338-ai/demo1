# Story 1.3：客户建立并终止安全登录会话

Status: done

## 用户故事

作为已注册客户，
我希望使用账号和密码安全登录及退出，
以便根据入驻状态查看审核结果或访问获准的平台能力。

## 验收标准

1. **有效凭据建立安全会话并按最新入驻状态分流**
   - **Given** 客户账号有效、未被登录锁定且登录标识与密码正确
   - **When** 客户提交登录请求
   - **Then** 系统在 Redis 建立服务端会话并通过 `HttpOnly`、`Secure`、`SameSite` Cookie 返回不可由前端脚本读取的会话标识
   - **And** 登录响应只返回安全的会话上下文、当前入驻状态和服务端决定的下一落点，不返回密码哈希、完整手机号、企业内部主键或其他敏感字段
   - **And** `PENDING_REVIEW`、`REJECTED` 默认落到入驻状态路由，`APPROVED` 默认落到平台总览

2. **认证与入驻授权分离并持续重新校验**
   - **Given** 已登录账号的入驻状态为 `PENDING_REVIEW` 或 `REJECTED`
   - **When** 访问控制台能力
   - **Then** 服务端仅允许会话、自身入驻状态、资料修正、退出及必要支持端点，其他受保护端点统一拒绝
   - **And** 前端转到入驻状态路由并使用文字说明限制原因，路由守卫不作为授权边界
   - **Given** 会话期间入驻状态发生变化
   - **When** 客户发起下一次受保护请求
   - **Then** 服务端依据持久化的最新状态重新授权，不依赖登录时写入会话的旧审核结论

3. **退出立即终止当前会话**
   - **Given** 客户持有有效会话
   - **When** 发起退出请求
   - **Then** 当前 Redis 服务端会话立即失效并清除 Cookie
   - **And** 使用原 Cookie 再访问任何认证端点均返回统一未认证结果，其他设备或浏览器的会话不受本次退出影响

4. **账号维度登录失败锁定**
   - **Given** 同一规范化账号在滚动 15 分钟内连续登录失败 5 次
   - **When** 该账号在锁定期内再次尝试登录
   - **Then** 拒绝登录 30 分钟并显示企业微信/邮件人工处理渠道
   - **And** 对不存在账号、密码错误和已锁定账号使用不可区分的对外凭据错误语义，不透露账号所属企业、手机号或审核状态
   - **And** 成功登录原子清除该账号的失败计数，过期失败记录不继续参与阈值计算

5. **IP 维度防暴力破解**
   - **Given** 同一可信来源 IP 在滚动 15 分钟内累计登录失败 20 次
   - **When** 该 IP 在限制期内发起新登录
   - **Then** 拒绝 30 分钟、返回稳定限流错误和 `Retry-After`，并记录不含凭据和完整请求体的安全指标
   - **And** 仅 TCP 对端属于配置的可信代理时才接受转发头中的客户 IP，非可信来源的转发头必须忽略
   - **And** 账号与 IP 两类计数分别执行，任一达到阈值均拒绝登录

6. **Redis 或关键认证依赖失败时关闭访问**
   - **Given** Redis 无法完成失败计数、锁定判断、会话创建、会话读取或会话删除
   - **When** 客户登录、退出或访问受保护能力
   - **Then** 系统失败关闭，不退化为进程内会话、不跳过锁定校验且不误报登录成功
   - **And** 返回统一、可重试的 `503`、Request ID 和安全提示，不暴露 Redis 地址、异常堆栈或内部配置

7. **登录页面可访问、可恢复且不泄露敏感数据**
   - **Given** 客户仅使用键盘、读屏或将页面缩放至 200%
   - **When** 输入凭据、处理校验错误、等待登录或完成退出
   - **Then** 字段有程序化标签，错误与字段关联，焦点移动到首个错误或结果标题，提交期间同步阻止重复操作
   - **And** 凭据失败后保留登录标识但清空密码，密码不进入 URL、Local Storage、Query Cache、日志、监控或测试快照
   - **And** 状态、锁定时间、支持渠道和下一动作使用文本表达，不仅依赖颜色

8. **契约、错误和请求标识一致**
   - **Given** 登录、会话查询或退出请求得到响应
   - **When** 前后端处理成功与失败结果
   - **Then** `contracts/openapi/console-v1.yaml` 是端点、Cookie、状态枚举和错误语义的唯一契约源，生成客户端不得手工修改
   - **And** 所有响应携带 Request ID；认证失败、锁定、限流、未认证和依赖不可用分别使用稳定错误码及统一 `code/message/requestId/details/retryable` 结构
   - **And** 错误响应不得泄露账号是否存在、密码校验分支、企业归属或入驻状态

## 开发注意事项

### 实施边界

- 本 Story 拥有登录、当前会话、退出、账号/IP 登录失败保护和基于最新入驻状态的授权分流。
- 本 Story 不拥有审核结果内容、驳回原因、资料修正或重提，这些属于 Story 1.4；仅提供其认证前置、授权扩展点和状态路由壳。
- 本 Story 不拥有内部审核/人工密码重置（Story 1.5）、可信企业租户上下文（Story 1.6）或不可变审计（Story 1.7）。
- 不新增 JWT、OAuth、短信验证码、自助找回密码、多成员账号、匿名状态令牌或运营审核 Web 后台。

### 安全与一致性

- 认证回答“客户是谁”，入驻状态回答“当前能访问什么”。`PENDING_REVIEW`、`REJECTED` 可以建立受限会话，但不能访问已通过客户能力。
- 所有权和授权均从服务端认证主体与权威持久化状态解析；不得信任客户端传入的账号、企业、申请或状态字段。
- Spring Security 规则采用明确 allowlist 并以默认拒绝收口；方法/路由顺序必须有回归测试，前端路由守卫不作为安全证据。
- Cookie 会话依赖 Redis，关键会话和锁定判断失败时必须失败关闭。会话 ID、CSRF Token、密码及手机号不得进入日志和指标。
- 登录响应不直接承载审核原因等 Story 1.4 数据；只返回安全状态枚举和路由决策所需信息。

### 项目现状与复用

- 使用项目已锁定的 Java 21、Spring Boot 4.1.0、React 19.2.4、Vite 7.2.4、TypeScript 5.9.3、MySQL 8.4 和 Redis，不在本 Story 升级主版本。
- 复用 Story 1.2 已建立的账号规范化、自适应密码哈希、手机号指纹、统一 `ApiError`、`RequestIdFilter`、可信代理解析、Redis 原子防滥用和 OpenAPI 生成链。
- 现有 `SecurityConfiguration` 只具备注册放行基线；扩展时保持匿名端点最小化，并用测试证明未声明端点仍被拒绝。
