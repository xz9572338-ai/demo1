# Story 1.2：客户提交企业入驻申请

Status: done

## 用户故事

作为外部合作客户，
我希望使用企业及联系人信息提交入驻申请，
以便获得开放平台使用资格。

## 验收标准

1. **有效申请原子创建**
   - **Given** 访客进入注册页面
   - **When** 填写企业名称、联系人、手机号、账号和密码并提交有效信息
   - **Then** 系统在同一数据库事务中创建企业、账号和状态为 `PENDING_REVIEW` 的入驻申请
   - **And** 返回不可枚举内部主键的公开申请标识、提交时间、状态、处理渠道和下一步说明
   - **And** 页面进入持久提交结果视图，不自动建立登录会话，待审核账号不能访问受保护功能

2. **字段校验与输入恢复**
   - **Given** 必填字段为空、手机号不是合法中国大陆手机号、账号不符合契约或账号已存在
   - **When** 客户提交
   - **Then** 系统不创建或部分创建企业、账号及申请
   - **And** API 使用统一错误结构返回稳定错误码和字段级 `details`
   - **And** 页面在对应字段附近显示问题，将焦点移至首个错误字段，并保留密码以外的其他已填内容

3. **重复与并发提交安全**
   - **Given** 同一账号被重复或并发提交，或客户端因网络不确定性重试同一次提交
   - **When** 服务端处理请求
   - **Then** 数据库唯一约束保证最多创建一组有效记录，不产生孤立企业、账号或申请
   - **And** 已存在账号统一返回 `ACCOUNT_ALREADY_EXISTS`，响应不得泄露该账号所属企业、手机号或审核状态

4. **敏感数据保护**
   - **Given** 入驻数据进入应用、数据库、日志或页面
   - **When** 系统处理密码和手机号
   - **Then** 密码只以 Spring Security `PasswordEncoder` 产生的带算法标识自适应单向哈希保存，任何持久化对象、响应及日志均不含明文密码
   - **And** 手机号规范化后以不低于 AES-256 强度加密保存，密钥从运行环境注入且不得与密文同库保存
   - **And** 页面或响应如需回显手机号仅显示前三后四位，访问日志、应用日志和错误日志不含完整手机号、密码、请求体或内部堆栈

5. **键盘与 200% 缩放可用**
   - **Given** 客户仅使用键盘或将页面缩放至 200%
   - **When** 填写、修正并提交注册表单
   - **Then** 所有字段具有程序化标签、错误与字段建立关联、提交按钮可操作且加载期间防止重复提交
   - **And** 校验失败时焦点移至首个错误字段，成功时焦点移至提交结果标题，并通过文本而非仅颜色表达状态和下一步

6. **契约、时间与请求标识一致**
   - **Given** 客户提交注册请求
   - **When** API 返回成功或失败
   - **Then** `contracts/openapi/console-v1.yaml` 是请求、响应、字段约束和错误语义的唯一契约源
   - **And** 所有响应携带全链路唯一 Request ID，提交时间以带时区 ISO 8601 返回并在界面按中国标准时间显示
   - **And** 匿名注册使用 Redis 跨实例共享且相互独立的防滥用与正常业务额度；仅可信代理可传递客户 IP，无效 CSRF 和超大请求只消耗防滥用额度
   - **And** 超大请求、不支持的媒体类型或字符集、额度超限、关键 Redis 判断不可用分别返回统一的 `413`、`415`、`429`、可重试 `503` 响应，且 `429` 携带 `Retry-After`

## 开发注意事项

### 实施边界与依赖顺序

- 本 Story 只拥有注册提交和 `PENDING_REVIEW` 初始状态；不实现登录/会话/锁定（Story 1.3）、审核结果查询/重提（1.4）、内部审核/人工密码重置（1.5）、可信租户上下文（1.6）或不可变审计（1.7）。
- 注册成功不代表审核通过，也不得生成沙箱/生产凭证、应用或权限。前端成功提示必须使用“申请已提交/待审核”，不得显示“注册成功即可使用”。
- 账号唯一性以服务端规范化后的值和数据库唯一约束为准；客户端预校验只能改善反馈，不能作为安全或一致性边界。
- 企业、账号和申请属于同一原子用例。不要先创建企业再异步补账号，也不要用补偿删除代替本地数据库事务。

### 契约与建议字段

- 请求字段：`enterpriseName`、`contactName`、`contactMobile`、`username`、`password`。全部去除首尾空白；账号按契约规定大小写规范化，企业/联系人原始业务字符不得擅自转码。
- 建议契约边界：企业名称 2–200 字符，联系人 2–100 字符，账号 4–64 个 ASCII 字母/数字及 `._-`，密码 12–128 个 Unicode 字符；禁止要求特定字符组合，允许密码管理器粘贴。手机号接受用户可读空格/连字符后规范化为 11 位中国大陆号码，再验证 `^1[3-9]\d{9}$`。
- 成功响应只返回 `applicationId`（公开申请标识）、`status`、`submittedAt`、`reviewRole`、`supportChannels`、`nextAction`、`requestId`；不得返回密码、手机号密文、手机号指纹、内部企业/账号主键。
- `ACCOUNT_ALREADY_EXISTS` 必须是账号冲突的统一外部语义。即使内部能识别企业或手机号，也不得通过差异化消息帮助枚举其他客户资料。

### 架构遵循与文件位置

- 后端放在 `apps/api/src/main/java/com/company/openplatform/identity/{api,application,domain,infrastructure}`；模块间不得直接访问 Repository/JPA 实体，`shared` 不承载企业或申请业务状态。
- 数据库仅通过 `apps/api/src/main/resources/db/migration/V*__*.sql` 变更；表/列 `snake_case`，约束使用 `uk_`/`fk_`/`idx_` 前缀，时间以 UTC 保存。
- 前端页面、表单、查询与 mutation 放在 `apps/web/src/features/onboarding/`；通用底层组件放 `components/ui`，只有稳定业务组合才放 `components/domain`。
- `contracts/openapi/console-v1.yaml` 是契约源。生成客户端位于 `apps/web/src/generated/api`，禁止手工编辑；若当前生成链尚未落地，先完善生成脚本再接入页面，不复制维护第二套 DTO。
- 统一错误和 Request ID 属于横切能力；若当前骨架尚无实现，可在 `shared/api`、`shared/observability` 建立最小可复用基线，后续故事必须复用。

### 安全与隐私防错

- Spring Security 推荐通过 `PasswordEncoder` 存储自适应单向哈希，并调优工作因子；故事实现不得存储可解密密码或快速摘要。优先使用带 `{id}` 的委托编码格式，为后续算法迁移保留空间。
- 手机号加密应通过专用端口封装，采用带随机 nonce 和认证标签的 AES-256-GCM（或达到 NFR14 且经架构批准的等价 AEAD），持久化只接收版本化密文。密钥不得进入 Git、前端、日志、数据库或测试快照；生产密钥缺失不得回退到示例值。
- 不记录注册请求体。异常日志仅记录 Request ID、结果分类和安全的技术上下文；`username`、手机号指纹等高基数字段不进入指标标签。
- 注册为公开写端点，必须设置合理请求体大小和速率保护接口，但登录失败锁定/IP 阈值属于 Story 1.3；本 Story 不应伪造审核或登录安全状态。

- Story 1.1 已建立 Java 21 + Spring Boot 4.1.0、React 19.2.4、Vite 7.2.4、TypeScript 5.9.3、MySQL 8.4、Redis、本地 Compose、OpenAPI/Flyway 校验及三条 GitHub required checks。
- 必须继续使用官方 Maven Wrapper、pnpm 锁文件和根工作区命令；不得依赖全局 Maven、H2、未锁定 `latest` 镜像或本机私有配置。
- 非本地配置必须失败关闭；本地端口只绑定回环地址；Testcontainers 已验证 MySQL 迁移，不要削弱既有安全和 CI 基线。
- 现有 `SecurityConfiguration` 仅放行健康端点且其余请求认证；本 Story 应最小化匿名注册放行范围，并用回归测试证明其他路径仍被拒绝。

### 测试要求与完成证据

- 每个 AC 必须至少有一项自动化证据；仅检查文件存在不算完成。
- 并发账号提交测试必须真实触发唯一约束竞争，断言仅一组记录存在且无孤立行；事务测试需在异常后检查三张表均无部分写入。安全回归还须验证缺失/错误 CSRF 令牌被拒绝、合法同域提交成功。
- 密码测试断言不等于原文、具有受支持算法标识且 `matches` 成功；手机号测试断言数据库、响应、日志均找不到完整输入号码。
- 可访问性除组件测试外，需验证错误摘要、`aria-describedby`/等价关联、焦点移动、Tab 顺序及 200% 缩放；不得只凭截图判断。

### 最新技术依据

- Spring Security 的 `PasswordEncoder` 专用于密码单向变换，推荐自适应算法并将工作因子调至当前系统可承受范围；带算法标识的委托格式支持后续升级。
- Spring MVC 对 `@Valid` 请求体和方法参数提供内建校验；应同时覆盖对象校验和方法校验的异常映射，避免校验错误绕过统一 API 错误契约。
- Spring Framework 支持集中处理 REST 错误，但本项目外部契约已固定为 `code/message/requestId/details/retryable`，实现应适配该契约，不并行暴露另一套默认错误结构。
