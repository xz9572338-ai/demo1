# Story 2.1：客户创建单一应用并首次领取沙箱密钥

Status: done

## Story

作为入驻审核通过的外部客户，
我希望创建本企业唯一的对接应用，并安全领取仅首次可见的沙箱 AppSecret，
以便开始后续接口权限申请与沙箱对接。

## 首发边界

- 每个企业最多一个应用；不实现多应用、停用/恢复、客户自助重置或 24 小时双密钥轮换。
- 本 Story 创建沙箱 AppID/AppSecret。生产凭证的人工签发和生产启用由 Story 5.3 承担，不得提前开放生产调用。
- 密钥遗失或疑似泄露由技术对接负责人按受控运维流程人工重置；不提供运营后台或客户侧重置入口。
- 不为延期能力预建 Outbox、动态配额、统计、密钥版本面板或 KMS 信封加密。首发使用受控 AES-256-GCM 配置，密钥与数据库密文分离。

## Acceptance Criteria

1. **创建唯一应用与沙箱凭证**
   - Given 当前 Cookie 会话有效且账号最新入驻状态为 `APPROVED`，企业尚无应用
   - When 客户提交合法的应用名称和用途
   - Then 平台在一个事务中创建归属当前企业、状态为 `ACTIVE` 的唯一应用，生成不可猜测且全局唯一的 AppID，并生成沙箱 AppSecret
   - And 返回 HTTP `201`、应用信息、`environment=SANDBOX`、AppID、AppSecret、`secretShownOnce=true` 和 Request ID
   - And AppSecret 明文只存在于本次响应，不写入数据库明文字段、URL、日志、监控、前端缓存或浏览器持久化存储。

2. **服务端阻止重复创建和并发穿透**
   - Given 当前企业已有应用，或同一企业并发提交创建请求
   - When 服务端处理请求
   - Then 数据库唯一约束保证最终最多一条企业应用记录；唯一成功请求返回 `201`，其余返回稳定 `APPLICATION_ALREADY_EXISTS` 冲突错误
   - And 冲突响应不生成或返回额外凭证，不以客户端按钮禁用代替服务端约束。

3. **未通过账号默认拒绝**
   - Given 会话账号状态为 `PENDING_REVIEW`、`REJECTED`、未知状态，或会话对应账号/企业已失效
   - When 直接调用应用创建或查询 API
   - Then 服务端按现有持续授权规则拒绝；未通过状态返回统一 `403`，身份数据缺失、漂移或存储故障按既有 `401/503` 规则处理
   - And 不创建应用、凭证或半成品记录。

4. **仅查询本企业应用且永不回显明文**
   - Given 审核通过客户查询应用
   - When `GET /console/api/v1/applications` 返回
   - Then 仅返回当前会话企业的零或一个应用，包含 applicationId、name、purpose、AppID、`SANDBOX`、状态、createdAt、updatedAt 和 Request ID
   - And 不返回 AppSecret、密文、IV、加密密钥版本或其他企业是否存在应用的信息。

5. **跨企业访问不泄露资源存在性**
   - Given 客户构造其他企业的 applicationId，或篡改请求尝试指定 enterpriseId
   - When 调用应用详情或相关端点
   - Then API 不接受客户端 enterpriseId 作为授权范围，并将越权资源按不存在处理
   - And 响应、日志和时序信息不得暴露其他企业的应用或凭证。

6. **仅首次展示的前端安全闭环**
   - Given 创建接口成功返回首次凭证
   - When 页面展示结果
   - Then 明确显示“沙箱环境”“仅展示一次”、AppID、AppSecret、安全保存说明，以及分别具备可访问名称的复制操作
   - And 复制成功/失败通过 live region 播报；确认框默认不勾选，确认保存后才允许正常离开结果状态
   - And 未确认时刷新、后退、关闭或站内导航触发明确警告；一旦离开或刷新，明文从组件内存清除，重新查询只能看到 AppID 和凭证已创建状态。

7. **失败不泄密且可恢复**
   - Given 创建、加密或持久化任一步失败
   - When 平台返回错误
   - Then 事务回滚，不保留无凭证应用或孤立凭证；统一错误包含稳定 code、message、Request ID、details 和 retryable
   - And 日志只记录 enterpriseId、applicationId（若已分配）、结果分类和 Request ID，不记录 AppSecret、密文、IV、完整请求体或内部堆栈。

8. **受控人工沙箱密钥重置**
   - Given 技术对接负责人收到客户通过企业微信/邮件提交的遗失或泄露请求，并完成双人复核
   - When 使用不暴露为 HTTP/客户页面的受控运维命令重置沙箱密钥
   - Then 新 AppSecret 仅在命令本次输出显示一次，旧密钥立即失效，操作记录 applicationId、环境、原因、操作人、复核人、时间和工单/沟通凭据
   - And 零行、多行、同人复核、非 `ACTIVE` 应用或依赖失败必须终止且不改变现有凭证。

9. **键盘、响应式与敏感值测试边界**
   - Given 客户使用键盘、Chrome/Edge 常用桌面宽度或 200% 缩放
   - When 创建应用、复制 AppID/AppSecret、确认保存并进入下一步
   - Then 焦点顺序与视觉顺序一致，Tab/Shift+Tab/Enter/Space 可完成流程，状态与环境不只靠颜色表达，页面无关键操作丢失或页面级横向滚动
   - And 自动化测试或测试替身不得把真实 AppSecret 写入快照、控制台输出或失败报告。

## Dev Notes

### 实现护栏

- 权威首发范围来自 PRD/Architecture 的“首发试点基线”和瘦身提案；后文完整一期的停用、轮换、KMS、生产凭证自助等要求不进入本 Story。
- OpenAPI 是控制台契约唯一来源。应用 API 使用 `/console/api/v1/applications`；变更请求继续使用现有 Cookie 会话与 CSRF。
- 后端沿用 `api/application/domain/infrastructure` 分层。事务边界在 application 用例层；application 与 credential 通过公开端口交互。
- 首发加密遵循本项目已批准的“受控加密配置”：AES-256-GCM、每次唯一 IV、密钥与密文分离。不得复用手机号加密的业务字段或把 AppSecret 交给密码哈希保存，因为 Story 5.1 需要使用明文密钥材料验证 HMAC。
- 首次 secret 响应应设置 `Cache-Control: no-store`；页面不得提供“眼睛”按钮或重新获取接口。
- Java 21 `SecureRandom` 是安全随机源；不要使用 `Random`、时间戳、UUID 文本拼接或自制 PRNG。JCA 保证支持 `AES/GCM/NoPadding`。
- 受控重置属于首发人工兜底，不得通过直接 SQL 拼接密文或公共 Controller 绕过领域校验。若安全地交付命令会显著扩大 Story，先记录阻塞，不得退化为可泄密脚本。

### 既有代码与复用点

- 会话主体与状态刷新：`apps/api/src/main/java/com/company/openplatform/identity/application/AccountPrincipal.java`、`identity/infrastructure/SessionStatusRefreshFilter.java`。
- 现有主体仅包含 accountId；`accounts.enterprise_id` 已由 Flyway V2 建立。application 模块应通过 identity 公开查询端口解析企业范围，不应扩大 Cookie/Session 中的缓存授权结论。
- 统一错误与 Request ID：`shared/api/ApiError.java`、`shared/observability/RequestIdFilter.java`、既有 exception handler。
- 模块骨架已存在：`apps/api/src/main/java/com/company/openplatform/application/`、`credential/`。
- 前端路由和守卫：`apps/web/src/app/App.tsx`、`features/auth/SessionGuard.tsx`；现有测试集中于 `App.test.tsx`，新增 feature 测试可相邻放置。
- 当前最新提交 `3f4840e` 完成 Story 1.4；其关键经验是服务端持续授权不能由前端守卫替代，数据库迁移需将加列、历史回填和约束分开，报告不得替代真实测试。

### 测试与完成门槛

- 本 Story 是安全敏感工作，但依据已批准的首发瘦身有意使用 `standard` profile；一次性密钥、租户隔离、并发唯一性、加密回滚和日志避敏均为阻断门槛。
- 依赖数据库行为的验证使用 MySQL Testcontainers；不得以 H2/Mock 代替唯一约束、事务和 AES 密文字段行为。
- 测试 secret 使用明确测试值并配置日志脱敏；失败信息只断言“不包含”，不要把 secret 作为快照内容。
- Story 未达到自动化证据、追踪矩阵和代码审查 Clean 前不得置为 done。
