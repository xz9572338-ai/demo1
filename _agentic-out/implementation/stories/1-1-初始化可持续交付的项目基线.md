# Story 1.1：初始化可持续交付的项目基线

Status: done

## 用户故事

作为交付团队，
我希望获得符合既定架构的可运行项目骨架，
以便后续功能能够在统一契约、模块边界和质量门槛上增量开发。

## 验收标准

1. **应用骨架**
   - **Given** 当前仓库尚无应用代码
   - **When** 完成项目初始化
   - **Then** 仓库包含 Java 21 + Spring Boot 4.1 的 `apps/api` 和 React + TypeScript + Vite + shadcn/ui 的 `apps/web`
   - **And** 根目录包含 Maven Wrapper、`pnpm-workspace.yaml`、锁定依赖的 `pnpm-lock.yaml`、`.env.example`、`README.md` 与统一工作区命令
   - **And** 后端包结构、前端 Feature 结构及契约、部署、测试目录与架构文档定义一致

2. **本地可运行性**
   - **Given** 开发者已安装 Java 21、Docker Compose 和满足 Vite 要求的 Node.js/pnpm
   - **When** 按 `README.md` 执行唯一组约定的本地启动命令
   - **Then** MySQL、Redis 和数据中台模拟服务通过 `deploy/compose/compose.local.yml` 启动并通过健康检查
   - **And** 后端 Actuator 健康端点返回可用状态，前端空壳页面可访问
   - **And** 本地配置和模拟数据不包含真实客户资料、真实密钥或生产标识

3. **可重复构建**
   - **Given** 新开发者获取仓库
   - **When** 仅使用仓库中的 Wrapper、锁文件和文档执行安装与构建
   - **Then** `apps/api` 在 Java 21 下完成 Maven `verify`，`apps/web` 完成独立 TypeScript 类型检查和 Vite 生产构建
   - **And** 不依赖未记录的全局工具或本机私有配置

4. **契约与迁移基线**
   - **Given** 项目骨架已创建
   - **When** 执行契约和数据库基线检查
   - **Then** `contracts/openapi/` 中的初始 OpenAPI 文档可解析且引用完整
   - **And** Flyway 至少包含可在空 MySQL 实例成功执行的基线迁移，且重复校验不产生校验和冲突

5. **CI 质量门槛**
   - **Given** 代码提交或合并请求触发 CI
   - **When** 流水线运行
   - **Then** 至少执行后端编译与测试、前端类型检查与构建、OpenAPI 校验和 Flyway 校验
   - **And** 各检查使用与本地一致的仓库命令，任意一项失败均使对应必需检查失败，从而阻止合并

## 开发注意事项

### 实施边界

- 本 Story 只建立可运行的交付基线；不实现注册、登录、企业建模、应用管理、签名、限流、三个查询端点或生产部署。
- 不引入微服务、Kubernetes、消息队列、SSR、Redux/Zustand 或第二套 UI 组件库。
- `contracts/openapi/` 是后续 API 契约唯一来源；本 Story 只创建最小有效骨架，业务模型由后续故事完成。
- 业务订单和客户事实不得写入平台 MySQL；Redis 不得成为业务事实源。

### 技术基线与防错

- Spring Boot 4.1.0 官方要求 Java 17–26，Java 21 符合架构决策；通过 Maven Wrapper 避免开发机 Maven 版本漂移。
- Vite 当前要求 Node.js 20.19+ 或 22.12+；项目统一选用 Node.js 22 LTS 且不低于 22.12。Vite 仅转译 TypeScript，必须独立运行 `tsc` 类型检查。
- shadcn/ui 组件源码存放在项目内；使用 `components.json` 和语义令牌保持一致，不将生成代码当作外部黑盒依赖。
- 容器镜像和 CI Action 使用明确主版本/受支持标签，禁止使用不可预测的 `latest`。依赖升级不在本 Story 内自动改变架构选型。
- `.env.example` 仅包含变量名和安全示例；真实凭据、签名、密钥和客户数据不得进入 Git、构建日志或前端静态资源。

### 项目结构说明

- 必须遵循架构文档的完整项目树；本 Story 仅需实体化支持编译、启动和校验的目录，但所有新文件必须放在其最终归属位置。
- 后端模块按 `api/application/domain/infrastructure` 组织，`shared` 不承载业务状态或用例。
- 前端 Feature 不直接跨越生成客户端访问后端；`components/ui` 不含业务规则，`components/domain` 不直接发起请求。
- 当前仓库无 Git 历史可用，且这是首个 Story，因此无前序故事实施经验可继承。

### 测试要求

- 后端至少覆盖应用上下文启动、健康端点和模块边界；MySQL 依赖行为使用 Testcontainers 真实容器，不以 H2 替代。
- 前端至少验证空壳页可渲染、关键标题可访问，并通过类型检查和生产构建。
- OpenAPI 校验必须能发现无效语法和断开引用；Flyway 校验必须在空 MySQL 上执行，不仅做文件名检查。
- 为每个验收标准保留可重现命令；不以“文件已存在”代替编译、启动、健康和失败路径验证。
