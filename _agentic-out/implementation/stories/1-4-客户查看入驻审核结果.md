# Story 1.4：客户查看入驻审核结果

Status: done

## Story

作为已提交申请并建立有效会话的外部客户，
我希望查看本人企业当前的入驻审核结果，
以便了解是否可以继续使用平台，或在线下处理驳回问题。

## Acceptance Criteria

1. **本人状态查询**
   - Given 客户持有有效服务端会话
   - When 调用 `GET /console/api/v1/onboarding/status`
   - Then 服务端仅按会话中的 `accountId` 反查其唯一入驻申请，不接受请求中的账号、企业或申请 ID
   - And 返回状态、提交时间、最后更新时间、审核角色、支持渠道、下一步提示和 Request ID。

2. **三种状态展示**
   - Given 查询结果为 `PENDING_REVIEW`、`APPROVED` 或 `REJECTED`
   - When 客户打开 `/onboarding/status`
   - Then 页面分别显示“待审核”“已通过”或“已驳回”及更新时间
   - And 仅驳回状态显示非空驳回原因；待审核提示等待商务审核；通过状态提供进入应用能力的主操作。

3. **线下受控审核立即生效**
   - Given 商务专员通过版本化受控 SQL 将待审核申请更新为通过或驳回
   - When 客户发起下一次状态查询或受保护请求
   - Then 申请状态与账号授权状态一致并立即生效，无需重新登录
   - And 操作记录结果、原因、操作人、复核人和审核时间；驳回原因必填，通过时驳回原因为空。

4. **持续授权与路由约束**
   - Given 当前账号不是 `APPROVED`
   - When 客户直接访问应用能力或调用非入驻状态白名单 API
   - Then 服务端返回统一 `403`，前端不能成为唯一授权边界
   - And 状态变为 `APPROVED` 后，下一次请求可以进入 `/dashboard`；状态页仍可查询本人最新结果。

5. **认证、隔离与异常处理**
   - Given 会话缺失、过期或对应账号不存在
   - When 查询审核结果
   - Then 返回统一 `401`，前端跳转登录页
   - And 任意客户均无法通过参数、路径或响应读取其他客户的申请；身份库不可用时返回无敏感信息的 `503` 与 Request ID。

6. **首发范围边界**
   - Given 申请被驳回
   - When 客户查看结果
   - Then 页面展示驳回原因以及企业微信/邮件支持渠道
   - And 不提供在线编辑、重新提交、运营审核后台、审核历史查询或客户可见的审核人信息。

7. **可访问与响应式体验**
   - Given 客户使用键盘、320/390px 视口或 200% 缩放
   - When 加载状态、重试、退出或进入下一步
   - Then 内容保持单列可读且无水平滚动，状态不能仅依赖颜色表达
   - And 焦点顺序符合 DOM 顺序，错误区域可被辅助技术识别，主操作可用 Tab 与 Enter 完成。

## Dev Notes

### 强制复用与边界

- 复用 Story 1.3 的 Redis Session、`AccountPrincipal`、`SessionStatusRefreshFilter`、`SessionGuard`、Cookie/CSRF 和统一 `RequestIdFilter`；不要创建匿名状态令牌、第二套登录态或前端本地授权缓存。
- `accounts.status` 是请求授权的即时来源，`registration_applications.status` 是审核结果来源。受控 SQL 必须原子同步二者；查询时若发现不一致，应失败关闭并留下不含个人信息的可诊断日志。
- 首发审核由商务专员线下执行。受控 SQL/runbook 属本 Story 交付物，但运营 Web 后台、在线修改重提、审核历史 UI 均属于 1.x。
- 支持渠道固定展示“企业微信 / 邮件”，不在仓库写入个人邮箱、手机号或企业微信账号。
- 不新增依赖或升级版本；技术版本沿用仓库锁文件和父 POM。当前功能不需要联网技术调研。
