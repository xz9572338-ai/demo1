# 产品简报：轻量化开放平台

## 执行摘要

当前外部合作客户主要通过微信、邮件索取数据，由内部人员人工导出 Excel 后发送；少量大客户则依赖一对一定制接口。该模式实时性差、易错漏，每新增一个客户都可能产生重复开发和沟通成本，也缺乏统一的调用监控与故障定位能力，无法支撑客户规模化接入。

轻量化开放平台将为现有长期合作企业提供标准化的 API 自助接入入口。客户通过 Web 控制台完成企业入驻、应用创建、接口权限申请、文档查阅、沙箱调试和调用统计，并使用 AppID 与签名访问获批接口。一期仅开放客户基础信息、订单列表和订单详情三个只读接口；内部审核暂由人员直接操作数据库完成，以最小投入尽快跑通完整接入闭环。

项目首要价值是消除重复的一对一定制开发，降低交付和运维成本；其次是把非标准沟通转化为可追踪的自助流程，将客户从注册到首次调试连通的平均周期控制在 5 个工作日以内。长期看，该平台将沉淀统一的开放 API、身份、授权和治理底座，为更多客户及业务能力的规模化开放提供基础。

## 问题与机会

现状给双方都带来持续摩擦：客户无法及时、自助地获取业务数据，必须反复沟通并等待人工处理；内部团队则承担重复导出、定制开发、问题排查和长期维护。流程、认证和接口规范因客户而异，导致交付周期不可预测，调用问题也缺少统一数据支撑。

首批仅有 8～12 家存量合作客户、8～15 个应用，适合采用轻运营模式先验证价值。通过标准接口替代 Excel 和点对点方案，可在有限范围内建立可复用的产品与治理模型，再依据真实申请量、调用量和运营负担决定二期投资。

## 目标用户与核心体验

主要用户是合作企业中负责系统对接的开发者或技术人员。他们需要清楚知道账号和权限状态，安全取得应用凭证，快速理解接口，并在不接触生产数据的情况下完成首次调用。核心“价值时刻”是开发者无需反复联系内部人员，即可在沙箱中成功调通获批接口，并能自行判断后续调用是否正常。

内部审核人员是重要协作方，但不是一期产品用户；其审核动作通过数据库操作完成。该临时方案必须通过受控脚本或存储过程执行，限制操作账号权限，并保留申请人、复核人、变更前后状态、原因和时间等审计记录，避免直接任意修改业务表。

## 一期解决方案

- 账号与入驻：客户填写企业、联系人和手机号注册；账号具有待审核、通过、驳回状态，只有审核通过后才能使用平台；支持账号密码登录。
- 应用与凭证：每家客户原则上创建一个对接应用；系统生成 AppID 和仅首次明文展示的 AppSecret；支持密钥重置和应用停用。沙箱与生产环境的凭证、域名、权限和限流策略相互隔离。
- 接口授权：应用可分别申请客户基础信息、订单列表、订单详情接口；前端展示待审核、通过、驳回状态，只有审核通过后才能调用。
- 文档与调试：以 OpenAPI 描述为文档、参数、示例和调试能力的统一来源；在线调试只连接使用模拟数据的沙箱环境，不访问生产环境。
- 调用统计：按应用展示近 7 天调用总量、成功数和失败数，并支持按接口筛选。
- 网关治理：采用 AppID + 请求签名，校验应用状态和接口权限，实施应用及接口维度的限流，并在网关、业务服务和数据访问层强制执行客户数据隔离。

客户完成沙箱调试后，还需通过生产接入验收才能访问真实数据。生产闭环至少包括客户身份与业务客户主数据绑定、生产权限确认、生产凭证签发、联调验收和正式启用；平台应记录各环节状态，避免“沙箱成功但无法上线”。三个首发接口的数据契约需支持稳定分页、时间范围或增量查询、明确的数据更新时间与历史范围，并规定字段脱敏和敏感数据可见规则。

## 产品原则与差异化

平台不追求一期覆盖通用 API 管理产品的全部能力，而是围绕存量合作客户提供最短、最清晰的接入路径：少量概念、明确状态、只读接口、隔离沙箱和可诊断调用结果。差异化来自对现有业务数据、合作关系和内部流程的直接适配，以及从人工交付到标准自助接入的执行效率，而非难以复制的技术壁垒。

安全上坚持默认拒绝和最小权限。签名应覆盖请求方法、路径、查询参数、关键请求头及请求体摘要，并包含时间戳和防重放信息；AppSecret 应加密保存或由专用密钥系统托管。密钥重置应考虑新旧密钥短暂并行的切换窗口。错误响应应提供统一错误码、Request ID，以及限流场景下的 429 和重试提示。

## 成功标准

- 首批至少 5 家客户完成注册并创建应用。
- 从客户注册到首次接口调试连通的平均周期不超过 5 个工作日。
- 接口首次调试连通成功率不低于 80%。
- 至少 6 个有效活跃应用，即近 30 天存在正常调用。
- 上线前记录每月人工导出次数与工时、定制接口平均交付工时和故障处理时长；一期复盘时对比平台实际替代量，量化节省的重复开发与维护投入。

指标口径在开发启动前固化：“首次调试连通”以应用首次在沙箱获得符合契约的成功响应为准；周期从注册申请提交开始计算；“正常调用”指排除平台内部测试后的生产成功调用。所有指标需明确统计窗口、数据源和责任人。

## 一期边界

一期不建设运营审核 Web 后台，不开放生产写入接口，不允许在线调试访问生产环境；同时不提供短信登录或通知、自助找回密码、Webhook、异常告警、SDK 资源管理、多版本接口管理、计费账单与流量套餐、客户多成员与组织管理、调用明细日志导出。平台也不承诺在一期替代所有历史定制接口。

由于尚无现成网关、账号体系、短信服务或日志统计底座，一期计划必须包含这些基础能力的建设或选型工作，并优先评估复用成熟网关、身份和可观测组件。身份与业务客户标识的绑定、跨租户隔离测试、凭证安全、审计留痕以及生产系统容量保护均为上线阻断项；数据库人工审核和人工密码重置属于明确的阶段性方案，而非长期运营模式。

## 演进方向

一期成功后，二期首先建设运营审核 Web 后台，将入驻和接口权限审核从数据库操作迁移为有权限控制、状态流转和审计记录的线上流程；其次扩充开放接口清单；随后增加调用异常告警和完整调用日志导出。客户多成员、接口版本管理和沙箱数据自助维护作为后续可选能力。

未来 2～3 年，平台可演进为公司统一的外部能力开放入口：以标准化接口目录、客户身份、应用凭证、权限策略、调用治理和审计体系，持续替代零散的数据交付与定制对接，同时保持按真实业务需求渐进扩展。
