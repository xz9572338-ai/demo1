# 轻量化开放平台：PRD 细节包

## 产品意图与业务背景

- 产品面向现有长期合作企业客户，由客户侧开发者通过 Web 控制台自助完成 API 接入；一期不服务内部运营人员。
- 当前主要交付方式是微信或邮件沟通后由内部人员人工导出 Excel；少量大客户采用一对一定制接口。
- 现状痛点包括人工导出效率低、实时性差且易错漏；新增客户重复开发；流程不标准、沟通和交付周期长；缺乏统一调用监控导致问题定位困难。
- 首要业务目标是消除大量一对一定制对接，降低重复开发和运维成本；次要目标是标准化流程、缩短接入周期并改善客户体验。
- 长期目标是沉淀公司统一的开放 API、身份、授权、治理与审计底座，支撑更多客户和业务能力规模化开放。

## 用户与规模

- 主要用户是合作企业中负责系统对接的开发者或技术人员；成功体验是无需反复联系内部人员即可理解接口、取得凭证、在沙箱完成首次调用并判断调用状态。
- 首批预计接入 8～12 家现有合作企业；每家原则上创建 1 个应用，总应用数预计 8～15 个。
- 内部审核人员是一期协作方而非产品用户；其操作方式是数据库侧受控回填，二期再提供 Web 运营后台。
- 建议选取 2～3 家首批客户作为共创对象，验证签名规范、字段语义、沙箱数据、分页和增量同步需求；该建议尚未被用户明确确认。

## 一期端到端场景

- 客户填写企业名称、联系人和手机号注册并提交入驻申请；账号状态至少包含待审核、通过、驳回。
- 未审核通过的账号不能使用平台业务功能；审核结果由内部人员在线下处理后写回数据库。
- 审核通过的客户创建应用，系统生成 AppID 和 AppSecret；AppSecret 仅首次明文展示。
- 客户按应用分别申请接口权限；权限状态至少包含待审核、通过、驳回，只有通过后应用才能调用对应接口。
- 客户在 API 文档中查看参数、响应示例和错误码，并通过页面调试工具向沙箱发起请求；沙箱使用模拟数据，不连接生产数据。
- 沙箱调试完成后进入生产接入验收；当前简报默认包含业务客户身份绑定、生产权限确认、生产凭证签发、联调验收和正式启用，但具体审批人与验收条件尚待 PRD 明确。
- 客户可按应用查看近 7 天调用总量、成功数和失败数，并按接口筛选。

## 一期功能需求提示

### 账号与入驻

- 注册字段已明确为企业、联系人、手机号；登录方式为账号密码。
- 需在 PRD 中定义账号唯一标识、手机号是否唯一、密码策略、登录失败保护、会话时长、安全退出和人工密码重置流程。
- 需定义入驻合法状态流转、驳回原因是否展示、驳回后是否允许修改重提，以及账号停用或撤销场景。
- 一期不做短信验证码登录、短信通知和自助找回密码；密码重置由内部人员人工处理。

### 应用与凭证

- 创建应用后生成 AppID 与 AppSecret；密钥只首次明文展示，支持重置，应用支持自主停用。
- AppSecret 不能按普通密码仅存不可逆哈希，因为 HMAC 类签名校验通常需要服务端取得验证密钥；应采用加密存储或专用密钥管理系统并严格限制访问。
- 密钥重置建议支持新旧密钥短暂并行及明确的旧密钥失效时间，避免客户生产切换中断；具体窗口未定。
- 沙箱与生产环境应使用不同域名、凭证、权限和限流策略，避免测试凭证访问生产资源。

### 接口权限

- 权限粒度为“应用 × 接口”，而不是只按企业或账号授权。
- 网关必须同时校验应用状态、接口权限、环境和限流策略，任何未知或缺失状态默认拒绝。
- 需定义申请原因等提交字段、重复申请规则、驳回后重提规则、授权撤销和应用停用后的权限行为。
- 一期数据库回填应通过受控脚本或存储过程完成，使用最小权限账号，并记录申请人、审核人或复核人、前后状态、原因和时间；不能允许任意直接修改业务表。

### 首发接口与数据契约

- 一期仅开放三个查询接口：客户基础信息查询、订单列表查询、订单详情查询；不允许任何生产数据写入。
- PRD 需为订单列表定义稳定分页、排序规则、时间范围或增量标识、单页上限、历史数据范围和数据更新时间。
- PRD 需明确客户基础信息和订单详情的字段清单、字段含义、可空性、枚举字典、数据时效、敏感字段脱敏和授权可见范围。
- 应验证三个接口是否覆盖历史 Excel 交付的主要数据需求，避免客户仍因缺少状态字典、关联资料或增量能力而继续索要定制接口。
- 建议统一响应结构、业务错误码、Request ID 和服务端时间；明确鉴权失败、权限不足、限流、参数错误、业务错误、超时及系统错误的分类。

### 文档与在线调试

- 建议以 OpenAPI 描述作为接口参数、返回模型、示例和调试工具的单一事实源，减少文档与真实接口不一致。
- 在线调试只调用使用模拟测试数据的沙箱环境，绝不连接生产环境。
- 沙箱字段、校验规则、签名规则和响应行为应尽量与生产一致，避免沙箱成功但生产失败。
- 无各语言 SDK 是一期明确边界，因此签名文档必须提供规范化字符串构造规则、编码规则、参数排序、时钟偏差处理和至少一种完整示例。

### 调用统计与可诊断性

- 控制台展示近 7 天调用总量、成功数、失败数，支持按接口筛选。
- PRD 需定义成功与失败口径，以及鉴权失败、权限拒绝、429、业务错误、超时和 5xx 是否及如何计数。
- PRD 需明确统计时区、数据延迟、刷新频率、保留时间和数据源。
- 一期不提供调用明细日志导出和异常告警，但 Request ID 与内部可检索日志仍应作为问题排查基础；只展示聚合统计不足以独立定位故障。

## 网关、安全与数据隔离约束

- 鉴权方式为 AppID + 请求签名；AppID 仅标识应用，不能单独承担认证和授权。
- 签名建议覆盖 HTTP 方法、路径、规范化查询参数、关键请求头和请求体摘要，并包含时间戳、有效期或容忍窗口以及 nonce 等防重放信息。
- 企业账号、应用、AppID 与内部业务客户主数据标识必须建立明确且唯一的绑定关系；任何绑定异常默认拒绝访问。
- 数据隔离不能只依赖前端或网关；网关通过后，业务服务和数据访问层仍须按租户或客户标识强制过滤和校验。
- 跨客户隔离测试、凭证安全、审核审计和生产系统容量保护属于上线阻断条件。
- 限流至少考虑全局、客户或租户、应用和接口维度；PRD 需定义默认速率、突发容量、特殊客户调整方式、429 响应与 Retry-After 行为。
- 批量拉取订单可能影响现有生产系统；需明确超时、最大查询范围、分页上限、重试建议、容量评估和下游熔断或保护策略。
- 企业联系人、客户资料和订单数据属于个人或商业敏感信息，需明确字段最小化、脱敏、传输加密、访问审计、日志避敏和留存策略。

## 成功指标及待固化口径

- 至少 5 家首批客户完成平台注册并创建应用。
- 客户从注册申请提交到首次在沙箱获得符合契约的成功响应，平均周期不超过 5 个工作日。
- 首次调试连通成功率不低于 80%；PRD 或数据方案需明确分子、分母、观察截止时间和排除条件。
- 至少 6 个有效活跃应用；当前定义为近 30 天存在排除内部测试后的生产成功调用。
- 上线前需建立人工导出次数与工时、定制接口平均交付工时、故障处理时长基线；一期复盘时衡量实际替代量。
- 用户尚未给出人工导出或定制开发成本的目标下降比例；可在立项或试点基线形成后再设目标。

## 一期明确排除项

- 不建设运营审核 Web 后台；数据库受控回填是阶段性方案。
- 不开放生产数据写入；三个首发接口全部为查询接口。
- 在线调试不访问生产环境，只使用沙箱模拟数据。
- 不实现短信验证码登录、短信通知、自助找回密码。
- 不实现 Webhook、调用异常告警、各语言 SDK 资源管理、多版本接口管理。
- 不实现计费、账单、流量套餐、客户多成员账号和组织架构管理。
- 不实现接口调用明细日志导出，也不承诺一期替代全部历史定制接口。

## 二期及后续优先级

- 第一优先级：运营审核 Web 后台，用线上权限控制、状态流转和审计替代数据库操作。
- 第二优先级：扩充业务开放接口清单。
- 第三优先级：调用异常告警和完整调用日志导出。
- 后续可选：客户多成员账号、接口版本管理、沙箱数据自助维护。
- 更长期可扩展到统一外部能力入口，但 webhook、事件接口或其他协议目前仅为研究启发，不属于已确认路线。

## 技术与交付上下文

- 当前无可复用的 API 网关、账号体系、短信服务或日志统计底座；一期必须包含基础组件选型或建设。
- 为保持“轻量化、快速落地”，应优先评估成熟网关、身份和可观测组件，避免从零自建签名、限流、日志和密钥管理的全部能力。
- 尚未明确上线时间、团队规模、部署环境、技术栈、自建或采购偏好，这些是后续架构和计划阶段的关键输入。
- 若交付受限，可讨论非核心体验的降级顺序，但生产身份绑定、授权、数据隔离、凭证安全、接口契约与审计不可降级。

## 行业研究信号

- Apigee、Azure API Management 等成熟产品采用“开发者或企业—应用—凭证—API 产品或权限—订阅审批—限流—分析”的通用模型，本产品对象模型符合行业惯例。
- Amazon API Gateway 等官方资料强调 API Key 不能单独作为身份认证或授权边界；配额和分布式限流通常是流量保护机制，不应作为严格计费或绝对安全保证。
- OpenAPI 适合驱动文档、示例和在线调试，并为后续 SDK、Mock、自动测试和版本治理预留演进空间。
- RFC 9421 的 HTTP 消息签名思路强调覆盖足够的请求组件，并使用 created、expires、nonce 等参数降低重放风险。
- OWASP API Security Top 10 强调对象级、属性级和功能级授权，以及资源消耗风险；客户数据隔离必须在业务和数据层实施。
- 产品的现实差异化不是技术壁垒，而是对公司现有业务数据、合作关系和内部流程的适配，以及替代人工交付的执行效率。

## 已识别但未决的问题

- 生产接入验收的负责人、审批条件、验收材料、SLA 和状态流转尚未确定。
- 三个接口的字段、分页、增量同步、历史范围、脱敏和数据时效尚未形成正式契约。
- 默认限流额度、突发策略和特殊客户额度调整流程尚未确定。
- 密钥轮换中新旧密钥并行窗口及旧密钥失效策略尚未确定。
- 注册驳回重提、接口申请重提、授权撤销、账号停用等完整状态机尚未确定。
- 一期上线时间、项目团队、部署架构、技术栈及组件选型尚未确定。
- 首批客户是否愿意迁移、是否具备自助 API 对接能力，以及三个接口的需求覆盖率仍需通过客户验证。
