# Sprint Change Proposal：Story 1.2 匿名注册分布式防滥用

## 1. 问题摘要

Story 1.2 复审发现匿名注册当前使用进程内、按 `remoteAddr` 计数的限流器。该实现无法在多实例间共享额度，可能把反向代理地址当作所有客户的共同来源，并且无法把无效 CSRF、超大请求等滥用流量与已通过安全门禁的正常注册业务流量分开。

用户于 2026-08-16 选择：使用 Redis 共享限流；仅在直接来源属于配置的可信代理时解析其转发客户端 IP；无效 CSRF 与超大请求只消耗独立防滥用额度，不消耗正常注册业务额度。

## 2. 影响分析

- Epic/PRD：不改变范围、用户价值或既有 FR/NFR，无需修改。
- Architecture：细化既有 Redis 原子限流、失败关闭和无状态横向扩展决策。
- Story 1.2：补充 AC6、任务 4、任务 6、测试证据和需求变更日志。
- UX：不改变页面流程；错误仍使用统一错误结构，并对 `413/415/429/503` 提供稳定语义。
- 技术：新增 Redis 数据访问依赖、原子计数脚本、可信代理配置、两类配额和 Redis Testcontainers 验证。

## 3. 推荐方案

采用直接调整，范围评定为 Minor：

1. 防滥用额度在安全链之前检查，覆盖匿名注册的所有 POST 请求；超大请求稳定返回 `413`。
2. 正常业务额度仅在请求已通过 CSRF、媒体类型、请求体和字段校验并进入注册用例前消耗。
3. 两类额度使用不同 Redis 键前缀和 TTL，通过原子操作跨实例共享。
4. 仅可信代理可提供转发客户端 IP；其他来源一律使用 TCP 对端地址。
5. Redis 无法完成关键限流判断时失败关闭，返回可重试的统一 `503`，不得无保护放行。

预计增加少量后端配置、过滤器/服务和集成测试，不改变三个月 MVP 计划。

## 4. 具体修改

### Architecture

原：Redis 保存限流桶，关键限流不可用时失败关闭。

新：补充匿名注册使用跨实例共享的 `registration:abuse` 与 `registration:business` 键空间；可信代理转发地址规则；无效 CSRF/超大请求只计入防滥用额度；关键判断不可用返回统一 `503`。

### Story 1.2

原：公开注册仅要求“合理请求体大小和速率保护”。

新：AC6 明确 `413/415/429/503`、Redis 共享额度、可信代理来源与两类配额；任务 4 实现运行时行为，任务 6 使用 Redis Testcontainers 覆盖跨实例共享、分流及失败关闭。

## 5. 实施交接

- 负责人：Developer。
- 完成条件：Architecture 与 Story 写回一致；AC→Task→Test→Requirement Change Log 四链完整；后端、前端、OpenAPI、Flyway 全部验证通过。
- 风险控制：不得信任未配置来源的 `X-Forwarded-For`；不得因 Redis 故障回退为无限流；不得让滥用请求耗尽正常业务额度。
