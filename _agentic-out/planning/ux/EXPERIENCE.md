# EXPERIENCE

本文件定义客户 Web 控制台的实现级行为、流程、信息架构和状态合同。视觉值统一引用 [DESIGN.md](DESIGN.md)，不在本文件重复定义。

## Pilot Scope Override

2026-08-17 批准的首发主路径为：注册 → 登录查看审核状态 → 审核通过后创建唯一应用并首次保存沙箱密钥 → 提交三个固定接口权限并查看状态 → 阅读静态 OpenAPI/签名示例 → 客户系统沙箱联调 → 技术负责人线下开通生产。

首发路由仅需注册、登录、入驻状态、应用、权限和 API 文档；不建设平台总览、应用多页签工作区、在线调试、调用统计、密钥轮换、停用/恢复、生产准入和问题工单。驳回资料修改重提改为线下沟通。后文相应流程、页面、状态和组合组件全部作为 1.x 体验储备，不阻塞首发；认证、租户隔离、一次性密钥保护、错误码/Request ID 和键盘可用性仍为首发要求。

## Users And Journeys

### Primary user

- **外部合作客户开发者：** 注册企业、查看审核状态、创建应用、管理凭证、申请接口权限、阅读文档、沙箱调试、完成生产准入并查看调用统计。

### Collaborating roles

- **商务专员：** 线下审核入驻资质；结果通过受控数据库流程回填。
- **业务产品：** 逐接口审核权限申请。
- **技术对接负责人：** 承接调试与生产问题，执行上线验收并协同运维。
- **运维：** 依据 Request ID、环境、接口和时间排查网关、日志及服务故障。
- **产品负责人：** 汇总三个月成效数据并形成二期建议；一期无平台内运营页面。

### Named journeys

1. 客户注册并完成首次生产接入。
2. 客户从签名、权限、限流或下游故障中恢复。
3. 客户安全轮换 AppSecret。
4. 内部人员完成入驻、接口权限及生产验收分工。
5. 产品与业务完成上线后三个月成效评估（外部运营程序）。

## Information Architecture

### Public and restricted routes

| Area | Purpose | Access rule |
|---|---|---|
| 注册 | 提交企业入驻申请 | 匿名；CSRF 与防滥用保护 |
| 登录 | 建立客户会话 | 已注册账号 |
| 入驻状态 | 查看待审核、通过、驳回及原因 | 已登录；未通过用户默认落点 |
| 平台总览 | 查看六阶段接入进度和下一步 | 入驻通过 |
| 应用 | 查看、创建、停用/恢复应用 | 入驻通过 |
| 应用工作区 | 概览、凭证、权限、调试、统计 | 当前企业拥有该应用 |
| API 文档 | 公共指南、端点、错误码、示例 | 入驻通过；权限状态就地说明 |
| 支持 | 企业微信/邮件渠道与问题信息清单 | 已登录 |

### Stable navigation

- 一级导航：总览、应用、API 文档、支持。
- 应用工作区页签：概览、凭证、接口权限、沙箱调试、调用统计。
- 页面标题区：面包屑、页面标题、当前状态、唯一主要操作。
- 持续上下文：企业、当前应用、应用状态、环境、最近更新时间。
- 筛选、分页、选中接口等可分享状态写入 URL；敏感信息禁止进入 URL、缓存或持久化浏览器存储。

## Primary Flows

### 1. Enterprise onboarding and review correction

1. 客户填写企业名称、联系人、手机号、账号和密码并提交。
2. 成功后显示申请编号、待审核状态、提交时间、商务专员和支持渠道。
3. 待审核状态不展示不可用平台功能，不显示虚假进度或预计完成时间。
4. 客户以已注册账号登录；服务端读取最新入驻状态并确定落点。
5. 待审核客户进入入驻状态页；审核驳回客户进入同一状态页，显示具体原因、可编辑字段和“修改并重新提交”，重提成功回到待审核。
6. 审核通过客户进入总览并突出“创建应用”；已通过或待审核申请不得重复提交。

登录成功后的固定分流为：`PENDING_REVIEW -> 入驻状态页`、`REJECTED -> 入驻状态页及修改重提`、`APPROVED -> 平台总览`。认证只确认客户身份，入驻状态决定授权范围；服务端在后续请求中按最新状态重新授权，前端路由守卫仅负责体验。

### 2. First production access

1. 总览识别当前接入阶段并提供唯一推荐动作。
2. 无应用时创建应用；创建后首次展示 AppID/AppSecret，确认保存前不得静默离开。
3. 对客户基础信息、订单列表、订单详情逐接口申请权限。
4. 权限通过后阅读签名说明并进入固定沙箱调试；失败结果关联错误解释和 Request ID。
5. 三接口调通后提交生产验收；仅展示未通过的门禁项和责任渠道。
6. 验收通过后获得独立生产凭证；首次成功调用后更新接入完成状态和调用概况。

### 3. Failure diagnosis and recovery

1. 捕获环境、应用、接口、时间、HTTP 状态、业务码与 Request ID。
2. 按签名/时间戳、应用/权限、限流、业务错误、下游异常、平台故障分类。
3. 每类错误提供原因、客户可执行动作、是否可重试和关联文档。
4. `429` 显示限流值与 `Retry-After`；下游异常不得展示陈旧或部分数据。
5. 自助恢复失败时，生成可复制的问题信息清单，通过企业微信或邮件升级技术负责人。

### 4. AppSecret rotation

1. 凭证页展示当前环境、凭证状态和重置影响。
2. 二次确认后生成新密钥并开始 24 小时并行窗口。
3. 新 AppSecret 仅首次展示；用户复制并确认保存后才可关闭完成状态。
4. 用户使用新密钥验证；失败时明确旧密钥仍可用及剩余时间。
5. 默认 24 小时后旧密钥失效；提前失效需要更高强度确认并说明生产中断风险。
6. 完成后更新状态并保留审计提示，不再展示密钥明文。

## Screen And State Inventory

| Screen / component | Required states |
|---|---|
| 注册页 | 初始、客户端校验、提交中、服务端字段错误、冲突、限流、服务不可用、成功 |
| 入驻状态页 | 待审核、通过、驳回、重提中、重提成功、加载/刷新失败 |
| 登录页 | 初始、校验、提交中、凭证错误、账号/IP 锁定、待审核/驳回重定向、成功 |
| 平台总览 | 无应用、接入进行中、阻塞、接入完成、加载、局部失败 |
| 应用列表 | 空、加载、正常、停用、操作中、操作失败 |
| 应用概览 | 沙箱/生产、门禁未完成、可验收、验收失败、生产启用 |
| 凭证页 | 未创建、仅首次展示、已复制、复制失败、轮换中、旧密钥即将失效、完成 |
| 权限页 | 未申请、待审核、通过、驳回、撤权、提交中、失败 |
| API 文档 | 加载、正常、端点选中、无权限说明、契约加载失败 |
| 沙箱调试 | 未配置、字段错误、发送中、成功、业务失败、网络失败、超时 |
| 调用统计 | 加载、空、正常、部分数据不可用、刷新失败 |
| 危险确认 | 说明、确认输入不匹配、提交中、成功、失败、取消 |

## Interaction Behavior

- 每个页面或面板最多一个推进当前阶段的主操作；已完成信息折叠为摘要，阻塞和失败保持展开。
- 所有提交防重复；按钮在进行中保留宽度和标签上下文。
- 字段错误就近展示，错误摘要链接到字段；提交失败保留非敏感输入并清空密码/密钥。
- 成功后移动焦点到结果标题或状态区域；错误后移动到首个错误字段/错误摘要。
- 状态变化后刷新当前资源并显示更新时间；不得只依赖短暂 Toast。
- 复制 AppID、Request ID、错误码和示例时，提供可访问名称及成功/失败播报。
- Dialog/AlertDialog 关闭后焦点返回触发元素；危险确认初始焦点位于取消操作。
- 沙箱调试器持续显示沙箱环境，不提供生产切换入口。
- 环境、应用与权限上下文在页面间保留，但 AppSecret 仅留在首次展示组件内存，离开后清除。
- 移动端保留状态查看、凭证应急操作和问题诊断；复杂文档和批量配置可明确建议桌面完成。

## System States

### Empty

- 说明为什么为空、是否属于正常初始状态，并提供唯一主要动作。
- 无应用时推荐创建应用；无调用时说明统计窗口和触发条件；审核等待绝不表现为空白页。

### Loading

- 首次加载使用与最终结构一致的 Skeleton。
- 表格刷新保留表头与已有数据；状态刷新显示更新时间，不阻塞无关区域。
- 长处理显示文字说明；提交操作禁止重复触发。

### Error

- 错误必须包含可理解说明、稳定错误码、Request ID（如存在）、是否可重试和下一动作。
- 字段错误不升级为页面故障；页面/依赖故障使用持久反馈并保留安全输入。
- 权限、应用状态和生产门禁错误直接链接相应状态页面；跨系统故障提供人工升级信息清单。
- 不显示内部堆栈、密钥、完整手机号、详细地址或业务响应敏感内容。

### Success

- 短操作可使用轻提示；阶段性成功必须使用持久结果区。
- 结果区显示完成内容、时间、状态和唯一下一步。
- 注册成功表达“申请已提交/待审核”，不得暗示已获平台访问权。
- 首次调试与生产调用成功保留环境、接口、耗时和 Request ID。

## Accessibility Requirements

- 注册、登录、审核状态、应用、凭证、权限、文档、调试和统计关键流程均可仅用键盘完成。
- 焦点顺序与视觉顺序一致；Tab/Shift+Tab 可遍历全部交互元素，Enter/Space 按控件语义工作。
- 所有字段具有持久可见标签；必填、错误、帮助文本通过语义属性关联。
- 状态变化通过文本和适当 live region 传达；状态与环境不只靠颜色。
- 表格提供正确表头；窄屏转换后每个值仍有标签。
- 触控目标不小于设计契约规定；200% 缩放下关键内容与操作无页面级横向滚动。
- 图表同时提供文字摘要或数据表；复制按钮说明复制对象和结果。
- 支持 `prefers-reduced-motion`；动画不得阻碍操作或成为唯一反馈。
- 自动检查结合 axe 等工具；每个关键 Story 仍需真实键盘和响应式人工验收。

## Design Token References

- 所有颜色、字体、间距、布局、圆角、边框、阴影、焦点与动效规则均来自 [DESIGN.md](DESIGN.md)。
- EXPERIENCE 只定义状态含义和交互结果；组件不得在业务页面新增未登记的视觉语义。
- 新状态需要先明确业务枚举，再在 DESIGN 中建立 token/图标映射，最后在组件中实现。

## Implementation Handoff

- 架构边界：React + TypeScript + Vite SPA；React Router 数据路由；TanStack Query 管理服务端状态；React Hook Form 管理表单；OpenAPI 生成客户端是类型来源。
- 目录边界：页面、查询、mutation 和流程组件放入对应 `features`；基础组件位于 `components/ui`；稳定复用的业务组合组件位于 `components/domain`。
- 敏感值不得进入 Query Cache、URL、localStorage、日志、监控或测试快照。
- 推荐组合组件：`OnboardingTracker`、`ReviewStatusPanel`、`OneTimeSecretReveal`、`SecretRotationPanel`、`PermissionMatrix`、`SandboxRequestRunner`、`ResponseInspector`、`DangerActionDialog`。
- 每个组合组件至少覆盖默认、加载、空、错误、成功、禁用和适用的危险状态；以可观察行为而非内部实现作为测试断言。
- Story 1.3 应先建立客户密码会话、退出、锁定及按最新入驻状态分流；Story 1.4 再实现“待审核/通过/驳回/修改重提”状态机、本人申请隔离、驳回原因、更新时间、支持渠道、错误恢复和键盘焦点，不提前实现运营审核 Web 后台。
- 一期 1.x 能力（页面沙箱调试、按接口筛选统计）必须继续按分期标签交付，不得被普通组件工作顺带扩入核心 MVP。
